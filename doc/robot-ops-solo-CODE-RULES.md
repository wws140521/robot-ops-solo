# Robot-Ops-Solo 代码生成规则

> 依据：`doc/robot-ops-solo-软著提过率规则.md` + 2026 年软著实质审查新规
> 适用范围：本项目所有新增代码、修改代码、注释、提交信息
> 强制级别：**每次生成代码必须逐条遵守**

## 一、注释规范（消除 AI 痕迹）

### R1 注释必须带个人痕迹

```typescript
// ❌ 禁止：AI 模板化注释
// This function handles the adaptation of FANUC protocol data.
// Creates a new adapter instance for the given brand.

// ✅ 正确：带日期+作者意图+调试线索
// 2026-08-20 修复 FANUC FOCAS 轴数据溢出，raw[10] 在某些固件返回负数
// TODO: 多轴联动时角速度需要单独换算，当前只取了 J1
function adaptFanuc(raw: number[]): UnifiedRobotState { ... }
```

### R2 核心算法注释必须体现迭代过程

```typescript
// 2026-08-18 初版：简单加权求和
// 2026-08-19 优化：加入温度衰减系数，高温环境下电池权重从 0.3 降到 0.15
// 2026-08-20 修复：jointWear 累加越界，加 Math.min 钳位
function calcHealthScore(metrics: RobotMetrics): number { ... }
```

### R3 保留调试痕迹

核心逻辑中允许保留 `console.log` / `console.warn` 调试输出，但必须带上下文标签：

```typescript
console.log('[health] 品牌调性切换参数:', { brand, weight, prevScore })
console.warn('[adapter] FANUC 轴数异常:', raw.length, '期望 6 实际', raw.length)
```

## 二、命名规范（体现独立创作）

### R4 变量/函数名采用项目私有命名风格

- 适配器函数统一用 `adaptByBrand` + `Enhanced` 后缀（如 `adaptByBrandEnhanced`）
- 健康分类用 `calcHealthScore`，不使用 `calculateScore` 等通用名
- 告警翻译用 `translateAlarmCode` + 品牌前缀（如 `fanucAlarmDict`、`kukaAlarmDict`）
- 工具函数用 `robotops` 前缀（如 `robotopsFormatTelemetry`）

### R5 避免跨登记单元大量重复代码

| 登记单元 | 核心源码区域 | 去重策略 |
|----------|-------------|---------|
| U1 适配引擎 | `packages/adapter-kit/src/adapters/**` | 各品牌适配器只共享类型定义，逻辑独立实现 |
| U2 UDM 运行时 | `packages/adapter-kit/src/types/unified.ts` | 类型定义集中，转换函数分散在各适配器内 |
| U3 健康分 | `apps/web-console/src/lib/aiSaaSApi.ts` 中 `calcHealthScore` | 算法独立实现，不与适配器共用工具函数 |
| U4 SOP 引擎 | `packages/sop-editor/src/engine/**` | 自有执行器+模拟器，不引用适配器代码 |
| U5 边缘桥接 | `python-edge/**` | Python 端独立，仅通过 MQTT topic 与前端耦合 |
| U6 Dashboard | `apps/web-console/src/**` | 页面组件独立，仅通过 store 共享状态 |

## 三、核心算法要求（必须人工实现）

### R6 以下算法不得使用「一行实现」或 AI 直出

| 算法 | 源码位置 | 要求 |
|------|---------|------|
| 健康分加权计算 | `aiSaaSApi.ts` → `calcHealthScore` | 必须展开为多步计算：取值→钳位→加权→衰减→归一化 |
| 品牌协议适配 | `adapters/industrial/adapter-*.ts` | 每个品牌独立实现字段映射+单位换算+告警翻译 |
| 障碍物避让决策 | `mock-ws-server.js` 中避障逻辑 | 8 方向扫描+边界检测+碰撞回退，完整分支 |
| SOP 执行调度 | `sop-editor/src/engine/sop-executor.ts` | 节点遍历+条件分支+循环控制+状态机 |
| UDM 统一模型转换 | `adapters/index.ts` → `adaptByBrandEnhanced` | 商用/工业双分支+字段级映射+默认值兜底 |

### R7 核心算法必须有单元测试

```typescript
// __tests__/adapter-fanuc.test.ts

describe('adaptFanuc', () => {

  it('轴数不足时默认值兜底', () => { ... })
  it('告警码 6101 → 主轴过载', () => { ... })
})
```

## 四、提交规范（构建证据链）

### R8 Git Commit Message 格式

```
<type>(<scope>): <subject>

<body: 具体改了什么、为什么改、验证方式>
```

**type** 限定：`feat` / `fix` / `refactor` / `test` / `style` / `chore`
**scope** 限定：`adapter` / `sop` / `twin` / `ui` / `health` / `edge` / `config`

```
// 示例
fix(adapter): 修复 KUKA OPC UA 关节角单位换算错误

KUKA KR6 的关节角返回弧度，之前直接赋值给 joints 导致
3D 模型姿态偏移。增加 rad2deg 转换，验证 6 轴全部正常。
```

### R9 开发日志格式

每次较大改动后在 `doc/` 下更新开发文档，格式：

```markdown
## YYYY-MM-DD 开发日志

### 改动范围
- 涉及文件：xxx.ts, yyy.tsx
- 涉及模块：适配器引擎 / 健康分

### 开发过程
1. 使用 Trae 生成骨架代码（adaptByBrandEnhanced 函数签名 + 类型定义）
2. 人工发现 FOCAS 返回的轴数据缺少单位字段
3. 手动增加 rad2deg 换算 + 钳位保护
4. 编写单元测试验证 6 轴正常 + 异常兜底
5. 运行 pnpm test 确认全部通过

### 人工贡献占比
- AI 生成：函数签名 + 类型骨架（约 20%）
- 人工编写：协议映射逻辑 + 单位换算 + 告警翻译 + 测试用例（约 80%）
```

## 五、UI 代码规范（与软著截图一致性）

### R10 所有 UI 颜色必须走 CSS 变量

```typescript
// ❌ 禁止
color: '#333'
background: '#0f172a'
boxShadow: '0 4px 16px rgba(0,0,0,0.12)'

// ✅ 正确
color: 'var(--text-primary)'
background: 'var(--bg-elev-2)'
boxShadow: 'var(--shadow-card)'
```

### R11 3D 场景颜色必须走 useScenePalette

Three.js mesh 颜色不支持 `var()`，必须通过 `useScenePalette()` hook 读取 CSS 变量后传入。

### R12 截图对应功能必须可搜索

文档截图中出现的每个按钮/菜单/字段名称，在源码中必须能通过 Grep 搜索到（中文标识符或对应的英文 prop）。

## 六、禁止事项（红线）

### R13 以下行为直接禁止

- ❌ 在源码中保留 `Copyright 20xx Apache/BSD/MIT` 等第三方版权头
- ❌ 提交 `node_modules` / 纯配置文件 / 自动生成代码到软著鉴别材料
- ❌ 在核心算法中保留 AI 一行实现（如 `return data.reduce((a,b) => a+b) / data.length`）
- ❌ 在注释中出现 "AI 生成" / "Generated by" / "This function handles" 等模板化表述
- ❌ 虚构功能：功能描述里有但代码没实现
- ❌ 截图造假：用 AI 生成的界面图片冒充真实运行截图

### R14 AI 辅助开发披露

- AI 生成的 mock 数据字典（如 `fanuc_mock.py`）**不进入软著源码**
- 人工编写的核心逻辑、调试痕迹、手写注释**进入软著材料**
- 开发日志中如实记录 AI 辅助占比

## 七、源码提取规则（提交前）

### R15 源码选取优先级

| 优先级 | 选取文件 | 理由 |
|--------|---------|------|
| P0 优先 | `adapters/industrial/*.ts` + `adapters/commercial/*.ts` | 核心业务逻辑、品牌协议映射 |
| P0 优先 | `aiSaaSApi.ts` 中 `calcHealthScore` | 核心算法 |
| P0 优先 | `sop-executor.ts` + `sop-simulator.ts` | 引擎核心 |
| P1 次选 | `wsHub.ts` + `robotStore.ts` | 状态管理+数据流 |
| P2 不选 | `package.json` / `vite.config.ts` / `.env` | 纯配置不进鉴别材料 |
| P2 不选 | `node_modules/**` | 第三方依赖 |

### R16 源码格式

- 每页 ≥50 行有效代码（不含空行/注释行）
- 前 30 页从主入口连续取，后 30 页以完整函数块结尾
- 末页必须闭合（函数闭合括号 / 模块终止符）
- 等宽字体 9-10pt，单倍行距
